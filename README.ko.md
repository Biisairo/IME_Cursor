# ImeCursor

[English](README.md) | [한국어](README.ko.md)

ImeCursor는 macOS 메뉴바 앱입니다. 현재 키보드 입력 소스를 마우스 포인터 옆에 작은 배지로 보여 줍니다. 원하면 글자를 입력하는 텍스트 캐럿 옆에도 배지를 보여 줍니다.

두벌식과 ABC처럼 입력 소스를 바꾸면 배지도 바로 바뀝니다. 그래서 메뉴바를 보지 않고도, 타이핑하기 전에 지금 어떤 언어로 입력될지 알 수 있습니다.

## 기능

- **모든 입력 소스 지원.** 시스템에 켜져 있는 입력 소스를 모두 읽어 옵니다. 한국어, 영어, 일본어 등 입력 소스마다 다른 배지를 설정할 수 있습니다.
- **캐럿 배지 (선택).** 텍스트 캐럿 옆에 배지를 하나 더 표시합니다. 타이핑하는 동안에는 시스템이 마우스 커서를 숨기고, 시선도 캐럿에 있습니다. 그래서 캐럿 배지가 있으면 입력하는 중에도 입력 소스를 바로 확인할 수 있습니다. 표시 조건은 "끄기", "커서가 숨겨졌을 때", "캐럿이 있으면 항상" 가운데 하나입니다. 이 기능은 접근성 권한이 필요합니다.
- **입력 소스별, 배지별 스타일 설정.** 표시 글자, 글자 크기와 굵기, 글자 색, 배경 크기와 색, 모서리 둥글기, 위치를 바꿀 수 있습니다. 배경 테두리와 글자 테두리도 넣을 수 있습니다. 입력 소스 화면에서는 바꾼 항목만 따로 저장하고, 바꾸지 않은 항목은 기본 스타일을 따릅니다.
- **위치는 기준 방향과 간격으로 지정.** 3 × 3 격자에서 기준 방향을 고르면, 배지가 포인터나 캐럿의 그쪽 바깥에 붙습니다. 그다음 X, Y 간격으로 위치를 세밀하게 맞춥니다. 캐럿 배지의 기본 위치는 캐럿의 오른쪽 위입니다. 배지가 입력 중인 줄 위에 있으므로, 조금 늦게 따라와도 방금 입력한 글자를 가리지 않습니다.
- **실시간 미리보기.** 설정 창에서 실제 시스템 커서(화살표 또는 I-beam)나 캐럿과 배지를 실제 크기로 함께 보여 줍니다.
- **Caps Lock 표시.** Caps Lock이 켜지면 배지 글자 앞에 `⇪`가 붙습니다.
- **전환 강조 (선택).** 입력 소스나 Caps Lock이 바뀌면 배지가 커졌다가 원래 크기로 돌아옵니다.
- **표시 모드.** 커서 배지와 캐럿 배지에 따로 정합니다.
  - 항상 표시
  - 전환 후 잠시 표시
  - 마우스가 멈추면 흐리게 (커서 배지만)
- **작업을 방해하지 않음.**
  - 타이핑할 때처럼 시스템이 커서를 숨기면 커서 배지도 숨깁니다.
  - 화면을 캡처하는 동안(Cmd+Shift+4 또는 Cmd+Shift+5)에는 배지를 숨깁니다.
  - Space를 전환할 때 배지가 화면과 함께 미끄러지지 않습니다.
  - 배지를 클릭하면 클릭이 배지 아래의 창으로 전달됩니다.
- **필요한 권한만 요청.** 캐럿 배지를 켤 때만 접근성 권한을 요청합니다. 캐럿 배지가 꺼져 있으면 어떤 권한도 요청하지 않습니다. 입력 모니터링 권한과 화면 기록 권한은 요청하지 않습니다.
- **가벼운 동작.** 유휴 상태의 CPU 사용률은 약 0.1~0.2%, 메모리 사용량은 약 17 MB입니다(개발 환경에서 측정).

## 설치

[Releases](https://github.com/Biisairo/IME_Cursor/releases) 페이지에서 `ImeCursor-<버전>.zip`을 받아 압축을 풉니다. 그다음 `ImeCursor.app`을 `/Applications`로 옮깁니다.

이 앱에는 ad-hoc 서명만 있고, 공증(notarization)은 받지 않았습니다. 처음 실행할 때 macOS가 실행을 막으면 다음 가운데 하나를 하세요.

- 시스템 설정 → 개인정보 보호 및 보안에서 **그래도 열기**를 누릅니다.
- 터미널에서 `xattr -dr com.apple.quarantine /Applications/ImeCursor.app`을 실행한 뒤 다시 엽니다.

직접 빌드하려면 아래 "빌드와 실행"을 보세요.

## 요구 사항

- macOS 14 (Sonoma) 이상
- Swift 6 도구 모음: Xcode 또는 Xcode Command Line Tools (`xcode-select --install`)

## 빌드와 실행

```sh
git clone https://github.com/Biisairo/IME_Cursor.git
cd IME_Cursor
./scripts/build_app.sh
open build/ImeCursor.app
```

`scripts/build_app.sh`는 다음 순서로 동작합니다.

1. `swift build -c release`로 release 실행 파일을 빌드합니다. 실행 파일은 `.build/release/`에 생깁니다.
2. 실행 파일, `Info.plist`, 앱 아이콘을 넣어 `build/ImeCursor.app`을 만듭니다.
3. 앱에 ad-hoc 서명을 합니다.

설치하려면 `build/ImeCursor.app`을 `/Applications`로 복사하면 됩니다.

이 앱에는 ad-hoc 서명만 있고, 공증(notarization)은 받지 않았습니다. 다른 Mac으로 앱을 옮기면 Gatekeeper가 실행을 막을 수 있습니다. 이때는 Finder에서 앱을 오른쪽 클릭한 뒤 **열기**를 선택하세요.

### 테스트 실행

```sh
./scripts/test.sh
```

Command Line Tools만 설치된 환경에서는 SwiftPM이 Swift Testing 매크로 플러그인을 찾지 못합니다. 그래서 `scripts/test.sh`가 Command Line Tools 위치의 플러그인 경로를 지정해 줍니다. Xcode가 설치되어 있으면 `swift test`를 바로 실행해도 됩니다.

### 릴리즈 만들기

```sh
./scripts/release.sh
```

이 스크립트는 `scripts/Info.plist`의 버전으로 `v<버전>` 태그와 GitHub 릴리즈를 만들고, `build/ImeCursor-<버전>.zip`을 첨부합니다. 릴리즈 본문은 `docs/releases/v<버전>.md`입니다. 실행 전에 다음을 확인하세요.

- 버전을 올렸고, 릴리즈 노트 파일을 만들었습니다.
- 모든 변경을 커밋하고 `origin/main`에 push했습니다.
- `gh`가 저장소에 쓰기 권한이 있는 계정으로 로그인되어 있습니다.

조건이 하나라도 맞지 않거나 테스트가 실패하면, 스크립트는 아무것도 올리지 않고 중단합니다.

### 캐럿 위치 진단

```sh
./scripts/caret_probe.sh [확인 주기(초)] [--enhanced]
```

캐럿 배지가 어떤 앱에서 동작하지 않을 때 원인을 찾는 도구입니다. 포커스 요소의 역할, 캐럿을 구한 방법, 편집 판별 신호를 터미널에 출력합니다. 그리고 찾은 캐럿에 빨간 테두리, 추정한 캐럿에 주황 테두리, 입력 요소에 노란 테두리를 그립니다. `--enhanced`를 주면 맨 앞 앱에 `AXEnhancedUserInterface`를 켭니다. 이 값은 그 앱을 종료할 때까지 남습니다. 이 도구를 실행한 터미널 앱에 접근성 권한이 있어야 합니다.

### 앱 아이콘 다시 만들기

아이콘 그림은 `Sources/ImeCursor/IconArtwork.swift`에 코드로 정의되어 있습니다. 이 파일을 고친 뒤에는 다음 명령을 실행하세요.

```sh
./scripts/make_icon.sh
```

이 스크립트는 `Resources/AppIcon.icns`를 만듭니다. 미리보기 PNG 파일은 `build/icon-preview/`에 저장합니다.

## 사용 방법

ImeCursor를 실행하면 메뉴바에 아이콘이 나타납니다. Dock에는 아이콘이 나타나지 않습니다.

| 메뉴 항목 | 동작 |
|---|---|
| 배지 표시 | 커서 배지와 캐럿 배지를 함께 켜거나 끕니다 |
| 설정… | 설정 창을 엽니다 |
| 종료 | ImeCursor를 종료합니다 |

설정 창 왼쪽 목록은 다음 순서입니다.

- **동작:** 로그인 시 자동 실행, 커서 배지 표시, 캐럿 배지 표시 조건, 접근성 권한 상태, 배지별 전환 강조와 표시 모드
- **기본 스타일:** 두 배지가 함께 쓰는 스타일입니다. 위치 기본값(기준 방향, X, Y)은 커서 배지와 캐럿 배지에 따로 있습니다.
- **커서 배지, 캐럿 배지:** 구역마다 켜져 있는 입력 소스를 나열합니다. 입력 소스 화면에서 항목을 바꾸면 그 항목만 덮어씁니다. 덮어쓴 항목에는 점과 되돌리기 버튼이 붙습니다. "초기화"를 누르면 그 배지의 덮어쓰기를 모두 지웁니다. 표시 글자는 두 배지가 함께 씁니다.

설정은 자동으로 저장되고, 바꾼 값은 배지에 바로 반영됩니다.

이전 버전의 설정은 처음 실행할 때 자동으로 옮깁니다. 커서 배지의 위치와 입력 소스별 스타일은 그대로 유지됩니다.

### 캐럿 배지 켜기

1. 설정 창의 **동작** 화면에서 캐럿 배지의 표시 조건을 고릅니다.
2. 접근성 권한을 요청하는 창이 뜨면, 시스템 설정에서 ImeCursor를 허용합니다.
3. **동작** 화면의 접근성 권한 상태가 "허용됨"으로 바뀌면 캐럿 배지가 동작합니다.

앱을 다시 빌드하면 접근성 권한을 다시 허용해야 합니다. ad-hoc 서명은 빌드할 때마다 바뀌고, 접근성 권한은 서명에 묶이기 때문입니다.

처음 실행하면 한국어 입력 소스는 파란 배지(`한`)로 시작합니다. 이 배지는 배경 색만 덮어쓰므로, 기본 스타일의 다른 항목을 바꾸면 함께 바뀝니다. 다른 입력 소스는 회색 기본 스타일을 씁니다. 기본 표시 글자는 입력 소스의 언어에 따라 정해집니다. 영어는 `A`, 일본어는 `あ`, 중국어는 `中`이고, 그 밖의 언어는 언어 코드를 씁니다.

## 동작 원리

| 항목 | 구현 |
|---|---|
| 입력 소스 감지 | Text Input Sources API(`TISCopyCurrentKeyboardInputSource`)와 분산 알림 `kTISNotifySelectedKeyboardInputSourceChanged` |
| 배지 | 테두리 없는 패널입니다. 클릭을 통과시키고, 전역 마우스 이동 이벤트를 받아 포인터를 따라갑니다 |
| 커서 표시 상태 | 폴링 주기마다 `CGCursorIsVisible`로 확인합니다. 이 함수는 지원이 중단되어서, 실행 시간에 `dlsym`으로 불러옵니다. 함수를 찾지 못하면 배지를 항상 표시합니다 |
| 화면 캡처 감지 | 300 ms마다 화면 위 창 목록을 확인합니다. 창 제목은 읽지 않고, 소유 프로세스와 레이어만 봅니다 |
| Caps Lock | 폴링 주기마다 `NSEvent.modifierFlags`로 확인합니다. 키 이벤트 모니터는 입력 모니터링 권한이 필요해서 쓰지 않습니다 |
| 캐럿 위치 | 접근성 API로 포커스 요소를 읽습니다. 편집할 수 있는 요소에서만 선택 범위의 끝을 캐럿으로 보고 화면 위치를 묻습니다. 앱이 위치를 주지 않으면 요소의 모양으로 추정하고, 추정도 안 되면 캐럿 배지를 숨깁니다 |
| Chrome 계열 브라우저 | Chrome은 `AXEnhancedUserInterface`를 켜야 입력란의 캐럿 위치를 알려 줍니다. ImeCursor는 캐럿 배지가 켜져 있을 때만 Chromium 브라우저에 이 값을 켭니다. 캐럿 배지를 끄거나 ImeCursor를 종료하면 다시 끕니다 |
| 폴링 주기 | 타이머는 하나만 씁니다. 평소에는 100 ms이고, 캐럿 배지가 켜져 있으면 키를 누르거나 포커스가 바뀐 뒤 1초 동안만 16 ms로 줄입니다 |
| Space | 배지 창은 현재 Space에만 속합니다(`moveToActiveSpace`). Space 전환이 끝나면 배지를 새 Space로 옮깁니다 |
| 설정 | 설정 창은 별도 프로세스(`--settings`)로 실행합니다. 그래서 설정을 편집하는 동안에도 배지가 포인터를 늦지 않게 따라갑니다. 두 프로세스는 `UserDefaults`를 공유하고, 변경 알림을 서로 주고받습니다 |

## 알려진 제한 사항

- 캐럿 배지는 접근성 API가 캐럿 위치를 주는 앱에서만 동작합니다. Java 앱이나 게임처럼 위치를 주지 않는 앱에서는 캐럿 배지가 나타나지 않습니다.
- Chrome에서는 캐럿 배지가 캐럿을 조금 늦게 따라갑니다. Chrome이 접근성 정보를 늦게 갱신하기 때문입니다. 캐럿 배지를 켠 직후 2 ~ 3초 동안은 Chrome에서 캐럿 배지가 나타나지 않을 수 있습니다.
- Chrome 계열 브라우저에 `AXEnhancedUserInterface`가 켜져 있으면, 창 관리 앱(Rectangle 등)의 창 이동이 느려질 수 있다는 보고가 있습니다.
- Space 전환 애니메이션 중에는 시스템이 마우스 이벤트를 보내지 않습니다. 그동안 배지는 보이지 않다가, 전환이 끝나면 다시 나타납니다.
- 화면 캡처를 시작한 뒤 배지가 사라지기까지 최대 0.3초가 걸릴 수 있습니다.
- Caps Lock 변경이 배지에 반영되기까지 최대 0.1초가 걸릴 수 있습니다.
- 글자가 배지 폭보다 넓으면 글자가 잘립니다. `⇪`도 폭을 차지하므로, 필요하면 배지 폭을 늘리세요.
