## 1. 서론

### 1.1 목적

이 문서는 ImeCursor의 요구사항을 정의한다. ImeCursor는 macOS에서 현재 선택된 키보드 입력 소스를 마우스 포인터 옆에 배지로 표시하는 상주 앱이다. 이 문서는 설계, 테스트, 구현, 인수의 기준이 된다.

### 1.2 범위

ImeCursor는 다음 일을 한다.

- 현재 선택된 키보드 입력 소스를 감지한다.
- 입력 소스에 맞는 배지를 마우스 포인터 옆에 표시한다. 커서가 숨겨졌을 때와 화면 캡처 중일 때는 배지를 숨긴다.
- 사용자가 활성화된 입력 소스마다 배지의 글자와 모양을 설정할 수 있게 한다.

다음 일은 이번 범위에 들어가지 않는다(비목표).

- 텍스트 캐럿 위치에 배지 표시 (2단계에서 검토)
- 설정 가져오기와 내보내기
- 앱별 예외 규칙 (특정 앱에서 숨기기 등)
- 마우스가 멈췄을 때 배지를 흐리게 하는 기능
- 자동 업데이트
- 입력 소스 전환 기능 (ImeCursor는 표시만 하고 전환하지 않는다)

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| 입력 소스 | macOS가 관리하는 키보드 입력 단위. 키보드 레이아웃(예: `ABC`)과 입력기 모드(예: `두벌식`)를 포함한다 |
| 입력 소스 ID | 입력 소스를 구분하는 문자열. `kTISPropertyInputSourceID` 값이다. 예: `com.apple.inputmethod.Korean.2SetKorean` |
| 활성 입력 소스 | 시스템 설정에 추가되어 있고 사용자가 선택할 수 있는 입력 소스 |
| 현재 입력 소스 | 지금 선택된 입력 소스 |
| 배지 | 마우스 포인터 옆에 표시되는 사각형. 배경과 글자로 구성된다 |
| 스타일 | 배지의 모양을 정하는 값의 묶음. 3.2.3절에 정의한다 |
| 기본 스타일 | 개별 설정이 없는 입력 소스에 적용하는 스타일 |
| 개별 설정 | 한 입력 소스에만 적용하는 스타일 |
| TIS | Carbon Text Input Sources API |
| 배지 프로세스 | 배지를 그리고 포인터를 추적하는 ImeCursor 프로세스. 인자 없이 실행된다 |
| 설정 프로세스 | 설정 화면만 띄우는 ImeCursor 프로세스. `--settings` 인자로 실행된다 |
| 캡처 창 | 창 목록(`CGWindowListCopyWindowInfo`)의 화면 위 창 가운데 다음에 해당하는 창. (1) 소유 프로세스 이름이 `screencapture`인 창 (Cmd+Shift+3/4). (2) 소유 프로세스 이름이 `Screenshot`이고 레이어가 화면 보호기 레벨(`CGWindowLevelForKey(.screenSaverWindow)`, 측정값 1000)보다 높은 창 (Cmd+Shift+5) |
| pt | macOS 좌표계의 포인트 단위 |

## 2. 전체 설명

### 2.1 제품 관점

ImeCursor는 단독으로 실행되는 macOS 앱이다. Dock 아이콘 없이 메뉴바 아이콘으로만 존재한다(`LSUIElement`). 다른 앱이나 서버와 통신하지 않는다.

구성 요소는 다음과 같다.

| 구성 요소 | 역할 |
|---|---|
| 입력 소스 감지기 | TIS API로 현재 입력 소스와 활성 입력 소스 목록을 읽는다. 변경 알림을 받는다 |
| 배지 창 | 테두리 없는 투명 창. 포인터를 따라 움직인다 |
| 포인터 추적기 | 마우스 이동 이벤트를 받아 배지 창의 위치를 갱신한다 |
| 숨김 감시기 | 100 ms마다 커서 표시 상태와 캡처 창을 확인하여 배지를 숨길지 정한다 |
| 설정 저장소 | 스타일을 `UserDefaults`에 저장하고 읽는다 |
| 설정 화면 | SwiftUI 창. 입력 소스별 스타일을 편집한다. 설정 프로세스에서만 실행된다 |
| 메뉴바 메뉴 | 배지 켜기/끄기, 설정 열기, 종료. 배지 프로세스에 있다 |

배지 프로세스와 설정 프로세스는 같은 실행 파일과 같은 번들 ID를 쓴다. 두 프로세스는 같은 `UserDefaults` 도메인을 공유하고, 분산 알림으로 설정 변경을 서로 알린다.

### 2.2 제품 기능 요약

1. 현재 입력 소스 감지와 변경 감지
2. 포인터 옆 배지 표시와 추적
3. 입력 소스별 스타일 설정과 미리보기
4. 설정 자동 저장
5. 로그인 시 자동 실행 선택

### 2.3 사용자 특성

사용자는 macOS를 쓰고 두 개 이상의 입력 소스를 전환하는 사람이다. 개발 지식은 필요 없다.

### 2.4 제약 사항

| ID | 제약 |
|---|---|
| C-1 | macOS 14 (Sonoma) 이상에서 동작해야 한다 |
| C-2 | Swift와 Apple 기본 프레임워크(AppKit, SwiftUI, Carbon, ServiceManagement)만 쓴다. 외부 패키지를 쓰지 않는다 |
| C-3 | Xcode 없이 Command Line Tools의 SwiftPM으로 빌드한다. `.app` 번들은 스크립트로 만든다. CLT에는 SwiftUI 매크로 플러그인이 없으므로 `@State` 등 매크로 기반 SwiftUI 속성을 쓰지 않는다. Swift Testing 매크로 플러그인 경로는 테스트 스크립트에서 지정한다 |
| C-4 | 접근성 권한, 입력 모니터링 권한 등 사용자 승인이 필요한 권한을 요구하지 않는다 |
| C-5 | 테스트는 Swift Testing 프레임워크로 작성한다 |
| C-6 | 네트워크를 쓰지 않는다 |

### 2.5 가정과 의존성

| ID | 가정 |
|---|---|
| A-1 | 마우스 이동 이벤트의 전역 모니터링(`NSEvent.addGlobalMonitorForEvents`)은 별도 권한 없이 동작한다 |
| A-2 | 입력 소스가 바뀌면 시스템이 `kTISNotifySelectedKeyboardInputSourceChanged` 분산 알림을 보낸다 |
| A-3 | 활성 입력 소스 목록이 바뀌면 시스템이 `kTISNotifyEnabledKeyboardInputSourcesChanged` 분산 알림을 보낸다 |
| A-4 | 배포 대상은 개발자 본인이다. ad-hoc 서명을 쓰고 공증(notarization)은 하지 않는다 |

| A-5 | `CGCursorIsVisible`은 다른 앱이 숨긴 커서도 반영한다 (2026-10-27 측정으로 확인함) |
| A-6 | Space 전환 중에는 전역 마우스 이벤트가 오지 않는다. `canJoinAllSpaces` 창은 창 레벨, `stationary`, `sharingType`과 관계없이 Space와 함께 미끄러진다 (2026-10-27 측정으로 확인함) |
| A-7 | `moveToActiveSpace` 창은 Space 전환 중 미끄러지지 않는다. 전환이 끝난 뒤 `orderFrontRegardless()`를 호출하면 새 Space에 표시된다. 미션 컨트롤에서도 숨김 처리 없이 정상으로 보인다 (2026-10-27 수동 시험으로 확인함) |
| A-8 | 화면 캡처 모드에서는 전역 마우스 이벤트가 오지 않는다. 캡처 모드 동안 캡처 창이 화면에 있다. 평소 `Screenshot` 프로세스에는 레이어 24 창만 있다 (2026-10-27 측정으로 확인함). 창 이름은 화면 기록 권한이 없으면 읽지 못할 수 있으므로 판별에 쓰지 않는다 |

A-1은 2026-10-27 수동 시험에서 확인했다.

## 3. 상세 요구사항

요구사항 문장에서 "해야 한다"는 필수, "할 수 있다"는 선택을 뜻한다.

### 3.1 외부 인터페이스

#### 3.1.1 사용자 인터페이스

| ID | 요구사항 |
|---|---|
| UI-1 | 배지는 둥근 사각형 배경과 그 가운데에 놓인 한 줄 글자로 구성해야 한다 |
| UI-2 | 배지 프로세스는 메뉴바 아이콘을 표시해야 한다. 메뉴 항목은 "배지 표시"(체크 표시 토글), "설정…", "종료"이다 |
| UI-3 | 설정 화면은 왼쪽에 입력 소스 목록, 오른쪽에 선택한 항목의 편집 영역을 두어야 한다 |
| UI-4 | 입력 소스 목록에는 "동작" 다음에 "기본 스타일"을 두어야 한다. 그 아래에 활성 입력 소스를 시스템 표시 이름으로 나열해야 한다 |
| UI-5 | 목록에서 현재 입력 소스에는 표시(예: 점)를 붙여야 한다 |
| UI-6 | 편집 영역 위쪽에 미리보기를 두어야 한다. 미리보기에는 시스템 커서 이미지와 선택한 스타일의 배지를 실제 크기로 함께 그린다. 배지는 FR-BADGE-2와 같은 규칙으로 커서의 핫스폿 기준 위치에 놓는다. 화면 경계 보정(FR-BADGE-3)은 하지 않는다 |
| UI-9 | 미리보기 위에 커서 종류 선택(화살표, I-beam)을 두어야 한다. 기본값은 화살표이다 |
| UI-10 | 미리보기 영역은 커서와 배지(테두리 포함)가 모두 들어가는 가장 작은 사각형에 사방 12 pt 여백을 더한 크기여야 한다 |
| UI-7 | 색상은 macOS 기본 색상 선택기(`ColorPicker`, 투명도 포함)로 고르게 해야 한다 |
| UI-8 | "로그인 시 자동 실행" 토글은 '동작' 화면(UI-11)에 두어야 한다 |
| UI-11 | 설정 화면 목록의 첫 항목은 "동작"이어야 한다. 그 아래에 "기본 스타일"과 입력 소스를 둔다. '동작' 화면에는 앱 전체에 적용되는 설정(FR-EMPH, FR-MODE, UI-8)을 둔다 |

#### 3.1.2 소프트웨어 인터페이스

| ID | 요구사항 |
|---|---|
| SI-1 | 현재 입력 소스는 `TISCopyCurrentKeyboardInputSource()`로 읽어야 한다 |
| SI-2 | 활성 입력 소스 목록은 `TISCreateInputSourceList`에 다음 조건을 주어 읽어야 한다: 카테고리 = `kTISCategoryKeyboardInputSource`, `kTISPropertyInputSourceIsSelectCapable` = true, 비활성 소스 제외 |
| SI-3 | 입력 소스 변경은 `DistributedNotificationCenter`에서 `kTISNotifySelectedKeyboardInputSourceChanged`를 구독하여 감지해야 한다 |
| SI-4 | 활성 목록 변경은 `kTISNotifyEnabledKeyboardInputSourcesChanged`를 구독하여 감지해야 한다 |
| SI-5 | 로그인 시 자동 실행은 `SMAppService.mainApp`의 `register()`와 `unregister()`로 처리해야 한다 |
| SI-6 | 커서 표시 상태는 CoreGraphics의 `CGCursorIsVisible`로 읽어야 한다. Swift에서 직접 호출할 수 없으므로 실행 시간에 `dlsym`으로 찾는다 |
| SI-7 | 캡처 창은 `CGWindowListCopyWindowInfo(.optionOnScreenOnly)`로 읽어야 한다 |
| SI-8 | Space 전환 완료는 `NSWorkspace.activeSpaceDidChangeNotification`으로 감지해야 한다 |
| SI-9 | 설정 변경 알림의 이름은 `com.dykim.ImeCursor.settingsChanged`이다. 알림의 object에는 보낸 프로세스의 PID 문자열을 넣어야 한다 |

### 3.2 기능 요구사항

#### 3.2.1 입력 소스 감지 (FR-DET)

| ID | 요구사항 |
|---|---|
| FR-DET-1 | 앱이 시작되면 현재 입력 소스를 읽고 그에 맞는 배지를 표시해야 한다 |
| FR-DET-2 | 현재 입력 소스가 바뀌면 배지의 스타일을 새 입력 소스의 스타일로 바꿔야 한다 |
| FR-DET-3 | 활성 입력 소스 목록이 바뀌면 설정 화면의 목록을 갱신해야 한다 |
| FR-DET-4 | 각 입력 소스에서 다음 값을 읽어야 한다: 입력 소스 ID, 시스템 표시 이름(`kTISPropertyLocalizedName`), 언어 목록의 첫 값(`kTISPropertyInputSourceLanguages`) |
| FR-DET-5 | 현재 입력 소스를 읽지 못하면 기본 스타일과 글자 `?`로 배지를 표시해야 한다 |

#### 3.2.2 배지 표시 (FR-BADGE)

| ID | 요구사항 |
|---|---|
| FR-BADGE-1 | 배지 표시가 켜져 있으면 배지를 표시해야 한다. 단, FR-HIDE의 숨김 조건에 해당하면 숨긴다 |
| FR-BADGE-2 | 배경 영역(테두리 제외)의 왼쪽 위 모서리는 포인터 위치에 스타일의 오프셋을 더한 위치에 놓아야 한다. X는 오른쪽이 양수, Y는 아래쪽이 양수이다. 배경 테두리는 배경 영역의 바깥으로 그린다(FR-STYLE-5) |
| FR-BADGE-3 | 배지(배경 테두리 포함)가 포인터가 있는 화면의 영역(`NSScreen.frame`)을 벗어나면, 배지를 그 화면 안쪽으로 옮겨야 한다. 화면 모서리에 붙여 넣는다 |
| FR-BADGE-4 | 다중 모니터 환경에서는 포인터가 있는 화면을 기준으로 FR-BADGE-3을 적용해야 한다 |
| FR-BADGE-5 | 마우스가 움직이거나 드래그될 때마다 배지 위치를 갱신해야 한다. 다른 앱이 앞에 있을 때와 ImeCursor 창이 앞에 있을 때 모두 해당한다 |
| FR-BADGE-6 | 배지 창은 마우스 이벤트를 받지 않아야 한다. 클릭과 스크롤은 배지 아래의 창으로 전달되어야 한다 |
| FR-BADGE-7 | 배지 창은 포커스를 가져가지 않아야 한다 |
| FR-BADGE-8 | 배지 창은 현재 Space에만 속해야 한다(`moveToActiveSpace`, `fullScreenAuxiliary`). 배지는 일반 Space와 전체화면 앱 Space 모두에서 표시해야 한다 |
| FR-BADGE-9 | 현재 입력 소스의 스타일에서 "표시"가 꺼져 있으면 배지를 숨겨야 한다 |
| FR-BADGE-10 | 메뉴바에서 "배지 표시"를 끄면 모든 입력 소스에서 배지를 숨겨야 한다. 이 값은 앱을 다시 시작해도 유지해야 한다 |
| FR-BADGE-11 | 스타일 값이 바뀌면 표시 중인 배지에 바로 반영해야 한다. 설정 프로세스에서 바꾼 값도 포함한다 |
| FR-BADGE-12 | Space 전환이 끝나면 배지를 현재 포인터 위치로 옮긴 뒤, 표시 조건을 만족하면 새 Space에 다시 표시해야 한다 |

#### 3.2.2A 배지 자동 숨김 (FR-HIDE)

| ID | 요구사항 |
|---|---|
| FR-HIDE-1 | 배지 프로세스는 100 ms마다 커서 표시 상태를 확인하고, 300 ms마다 캡처 창을 확인해야 한다. 창 목록 조회는 비용이 커서 PR-3을 지키기 위해 주기를 나눈다 |
| FR-HIDE-2 | 커서가 숨겨져 있으면 배지를 숨겨야 한다. 마우스 이동 이벤트를 받을 때에도 커서 표시 상태를 확인해야 한다 |
| FR-HIDE-3 | `CGCursorIsVisible` 심볼을 찾지 못하면 커서가 항상 보이는 것으로 처리해야 한다 |
| FR-HIDE-4 | 캡처 창이 하나라도 있으면 배지를 숨겨야 한다 |
| FR-HIDE-5 | (1.2에서 지움) |
| FR-HIDE-6 | 숨김 조건이 끝나서 배지를 다시 표시할 때는, 먼저 현재 포인터 위치로 배지를 옮긴 뒤 표시해야 한다 |
| FR-HIDE-7 | 숨김 조건은 FR-BADGE-9, FR-BADGE-10의 조건과 함께 적용한다. 하나라도 숨김이면 배지를 숨긴다 |

#### 3.2.2B Caps Lock 표시 (FR-CAPS)

| ID | 요구사항 |
|---|---|
| FR-CAPS-1 | 배지 프로세스는 FR-HIDE-1의 100 ms 주기마다 Caps Lock 상태를 `NSEvent.modifierFlags`로 읽어야 한다. 키 이벤트 모니터는 쓰지 않는다(C-4) |
| FR-CAPS-2 | Caps Lock이 켜져 있으면 표시 글자 앞에 `⇪`를 붙여 그려야 한다. 표시 글자가 비어 있으면 `⇪`만 그린다 |
| FR-CAPS-3 | `⇪`는 그릴 때만 붙인다. 저장된 표시 글자와 FR-SRC-5의 길이 제한에는 포함하지 않는다 |
| FR-CAPS-4 | 이 기능은 모든 입력 소스에 항상 적용한다. 끄는 설정은 두지 않는다 |

#### 3.2.2C 전환 강조 (FR-EMPH)

"전환"은 현재 입력 소스가 바뀌거나 Caps Lock 상태가 바뀌는 것을 말한다.

| ID | 요구사항 |
|---|---|
| FR-EMPH-1 | 전환 강조 설정은 켜기 여부, 확대 배율, 지속 시간으로 구성한다. 범위와 초기값은 다음과 같다: 켜기 여부(초기값 꺼짐), 확대 배율 1.0 ~ 3.0(초기값 1.6), 지속 시간 0.1 ~ 1.0초(초기값 0.35) |
| FR-EMPH-2 | 전환 강조가 켜져 있으면, 전환이 일어날 때 배지를 확대 배율로 키운 뒤 지속 시간 동안 원래 크기로 줄여야 한다. 확대와 축소의 중심은 배지(테두리 포함)의 가운데이다 |
| FR-EMPH-3 | 확대된 배지가 잘리지 않도록 배지 창은 `배지 전체 크기 × 확대 배율` 크기여야 하고, 배지는 창 가운데에 놓아야 한다. 화면 경계 보정(FR-BADGE-3)은 확대하지 않은 배지 기준으로 한다 |
| FR-EMPH-4 | 배지가 숨김 상태(FR-HIDE, FR-BADGE-9, 10)이면 강조하지 않는다 |
| FR-EMPH-5 | 범위를 벗어난 값은 가장 가까운 경계값으로 바꿔야 한다 |

#### 3.2.2D 표시 모드 (FR-MODE)

| ID | 요구사항 |
|---|---|
| FR-MODE-1 | 표시 모드는 "항상 표시", "전환 후 잠시 표시", "멈추면 흐리게" 중 하나이다. 초기값은 "항상 표시"이다 |
| FR-MODE-2 | 표시 모드 설정은 대기 시간(0.5 ~ 10초, 초기값 2초)과 흐린 정도(불투명도 0 ~ 1, 초기값 0.3)를 함께 가진다. 범위를 벗어난 값은 가장 가까운 경계값으로 바꿔야 한다 |
| FR-MODE-3 | "항상 표시"이면 배지 불투명도는 1이다 |
| FR-MODE-4 | "전환 후 잠시 표시"이면, 마지막 전환 뒤 대기 시간이 지나기 전에는 불투명도 1, 지난 뒤에는 0이다. 배지 프로세스가 시작된 시점도 전환으로 본다 |
| FR-MODE-5 | "멈추면 흐리게"이면, 마지막 마우스 이동 뒤 대기 시간이 지나기 전에는 불투명도 1, 지난 뒤에는 흐린 정도의 값이다 |
| FR-MODE-6 | 불투명도가 바뀔 때는 0.2초 동안 부드럽게 바꿔야 한다 |
| FR-MODE-7 | 표시 모드의 불투명도는 FR-HIDE의 숨김 조건보다 우선하지 않는다. 숨김 조건이면 표시 모드와 관계없이 숨긴다 |
| FR-MODE-8 | 불투명도는 FR-HIDE-1의 100 ms 주기마다 다시 계산한다 |

#### 3.2.3 스타일 (FR-STYLE)

FR-STYLE-1: 스타일은 다음 항목으로 구성해야 한다.

| 항목 | 타입 | 허용 범위 | 기본 스타일의 초기값 |
|---|---|---|---|
| 표시 여부 | Bool | — | 켜짐 |
| 글자 크기 | 실수 (pt) | 6 ~ 72 | 12 |
| 글자 굵기 | 열거형 | regular, medium, semibold, bold | semibold |
| 글자 색 | RGBA (각 0 ~ 1) | — | 흰색, 불투명도 1.0 |
| 배경 색 | RGBA (각 0 ~ 1) | — | 회색 (0.45, 0.45, 0.45), 불투명도 0.85 |
| 배경 폭 | 실수 (pt) | 4 ~ 200 | 22 |
| 배경 높이 | 실수 (pt) | 4 ~ 200 | 18 |
| 모서리 둥글기 | 실수 (pt) | 0 ~ 100 | 5 |
| 오프셋 X | 실수 (pt) | -200 ~ 200 | 16 |
| 오프셋 Y | 실수 (pt) | -200 ~ 200 | 16 |
| 배경 테두리 두께 | 실수 (pt) | 0 ~ 20 | 1 |
| 배경 테두리 색 | RGBA (각 0 ~ 1) | — | 검정, 불투명도 0 (투명) |
| 글자 테두리 두께 | 실수 (pt) | 0 ~ 10 | 1 |
| 글자 테두리 색 | RGBA (각 0 ~ 1) | — | 검정, 불투명도 0 (투명) |

| ID | 요구사항 |
|---|---|
| FR-STYLE-2 | 허용 범위를 벗어난 값은 가장 가까운 경계값으로 바꿔야 한다. 색의 각 성분도 0 ~ 1로 바꿔야 한다 |
| FR-STYLE-3 | 그릴 때 적용하는 모서리 둥글기는 `min(모서리 둥글기, 배경 폭 / 2, 배경 높이 / 2)`이어야 한다 |
| FR-STYLE-4 | 글자가 배경보다 넓으면 배경 밖으로 넘치지 않게 잘라서 그려야 한다. 글자 테두리도 같다 |
| FR-STYLE-5 | 배경 테두리는 배경 영역의 바깥에 그려야 한다. 배지 전체 크기는 (배경 폭 + 2 × 두께, 배경 높이 + 2 × 두께)이다. 바깥 모서리 반지름은 FR-STYLE-3의 반지름이 0보다 크면 `반지름 + 두께`, 0이면 0이다 |
| FR-STYLE-6 | 글자 테두리는 글자 모양의 바깥에 그려야 한다. 글자 획의 굵기는 테두리 두께와 관계없이 같아야 한다 |

#### 3.2.4 입력 소스별 설정 (FR-SRC)

| ID | 요구사항 |
|---|---|
| FR-SRC-1 | 입력 소스마다 "표시 글자"와 "스타일 모드"를 저장해야 한다. 키는 입력 소스 ID이다 |
| FR-SRC-2 | 스타일 모드는 "기본 스타일 사용" 또는 "개별 설정" 중 하나이다. "개별 설정"이면 그 입력 소스만의 스타일(FR-STYLE-1의 전체 항목)을 저장해야 한다 |
| FR-SRC-3 | "기본 스타일 사용"인 입력 소스는 기본 스타일로 그려야 한다. 기본 스타일이 바뀌면 이런 입력 소스의 배지에도 바뀐 값이 반영되어야 한다 |
| FR-SRC-4 | "기본 스타일 사용"에서 "개별 설정"으로 바꾸면, 그 시점의 기본 스타일 값을 개별 스타일의 시작값으로 복사해야 한다 |
| FR-SRC-5 | 표시 글자는 0 ~ 8자(문자소 단위)여야 한다. 8자를 넘는 입력은 앞의 8자만 남겨야 한다. 빈 글자를 허용한다. 빈 글자이면 배경만 그린다 |
| FR-SRC-6 | 저장된 설정이 없는 입력 소스의 표시 글자는 언어 코드로 정해야 한다: `ko` → `한`, `en` → `A`, `ja` → `あ`, `zh`로 시작 → `中`. 그 밖의 언어는 언어 코드의 앞 두 글자를 대문자로 쓴다(예: `de` → `DE`). 언어 코드가 없으면 시스템 표시 이름의 첫 글자를 쓴다. 이것도 없으면 `?`를 쓴다 |
| FR-SRC-7 | 저장된 설정이 없는 입력 소스의 스타일 모드는 다음과 같아야 한다. 언어 코드가 `ko`이면 "개별 설정"이다. 이 개별 스타일은 기본 스타일을 복사하되 배경 색만 파랑 (0.0, 0.48, 1.0), 불투명도 0.85로 바꾼 값이다. 그 밖의 언어이면 "기본 스타일 사용"이다 |
| FR-SRC-8 | 활성 목록에서 빠진 입력 소스의 설정은 지우지 않고 보관해야 한다. 다시 활성화되면 보관한 설정을 써야 한다 |
| FR-SRC-9 | 편집 영역에 "초기화" 버튼을 두어야 한다. 누르면 그 입력 소스의 저장된 설정을 지우고 FR-SRC-6, FR-SRC-7의 값으로 되돌려야 한다. 기본 스타일에서 누르면 FR-STYLE-1의 초기값으로 되돌려야 한다 |

#### 3.2.5 저장 (FR-STORE)

| ID | 요구사항 |
|---|---|
| FR-STORE-1 | 설정 값이 바뀌면 바로 `UserDefaults`에 저장해야 한다. 별도의 저장 버튼을 두지 않는다 |
| FR-STORE-2 | 설정은 JSON으로 인코딩한 한 개의 값으로 저장해야 한다. 이 값에는 스키마 버전 번호를 넣어야 한다. 현재 스키마 버전은 3이다 |
| FR-STORE-3 | 저장 대상은 다음과 같다: 스키마 버전, 배지 표시 여부(전역), 동작 설정(FR-EMPH-1, FR-MODE-1, 2), 기본 스타일, 입력 소스 ID별 설정 |
| FR-STORE-4 | 저장된 값을 디코딩하지 못하면 초기값으로 시작해야 한다. 이때 앱이 종료되면 안 된다. 손상된 원본 값은 다른 키에 백업해야 한다 |
| FR-STORE-5 | 저장된 값의 범위가 맞지 않으면 읽을 때 FR-STYLE-2를 적용해야 한다 |
| FR-STORE-6 | 스타일에 테두리 항목이 없는 저장값(스키마 버전 1)도 읽을 수 있어야 한다. 이때 없는 항목은 FR-STYLE-1의 초기값으로 채우고, 나머지 값은 그대로 유지해야 한다. 읽은 뒤의 스키마 버전은 현재 버전이다 |
| FR-STORE-7 | 동작 설정이 없는 저장값(스키마 버전 1, 2)도 읽을 수 있어야 한다. 이때 동작 설정은 초기값으로 채운다 |

#### 3.2.6 앱 수명 주기 (FR-APP)

| ID | 요구사항 |
|---|---|
| FR-APP-1 | 앱은 Dock 아이콘 없이 실행되어야 한다 |
| FR-APP-2 | "설정…"을 누르면 설정 프로세스를 실행해야 한다. 설정 프로세스가 이미 실행 중이면 새로 실행하지 않고 그 프로세스를 앞으로 가져와야 한다 |

| FR-APP-4 | `register()`나 `unregister()`가 실패하면 토글을 실제 상태로 되돌리고 설정 화면에 오류 문구를 표시해야 한다 |

#### 3.2.7 프로세스 분리 (FR-PROC)

| FR-PROC-1 | 실행 인자에 `--settings`가 있으면 설정 프로세스로, 없으면 배지 프로세스로 동작해야 한다 |

| FR-PROC-6 | 로그인 시 자동 실행은 배지 프로세스를 실행해야 한다 |

## 4. 검증

### 4.1 검증 방법

| 방법 | 대상 |
|---|---|
| 자동 테스트 (T) | QA-1의 순수 로직 모듈 |
| 수동 시험 (M) | UI, 실제 TIS 연동, 창 동작, 성능 |
| 검사 (I) | 코드와 빌드 설정 검토 |

### 4.2 요구사항별 검증

| 요구사항 | 방법 | 기준 |
|---|---|---|
| FR-DET-1, FR-DET-2, PR-1 | M | 두벌식 ↔ ABC 전환 시 배지가 바로 바뀐다 |
| FR-DET-3 | M | 시스템 설정에서 입력 소스를 추가하면 설정 화면 목록에 나타난다 |
| FR-DET-5 | T | 가짜 감지기가 nil을 반환하면 기본 스타일과 `?`가 나온다 |
| FR-BADGE-2, 3, 4 | T, M | 위치 계산 함수: 일반 위치, 오른쪽·아래쪽·왼쪽·위쪽 경계, 음수 오프셋, 두 번째 화면 |
| FR-BADGE-5 ~ 8, 12 | M | 다른 앱 위, 드래그 중, 클릭 통과, 전체화면 앱, Space 스와이프와 전환 뒤 재표시, 미션 컨트롤 |
| FR-BADGE-9, 10, 11 | T, M | 표시 여부 결정 로직은 T, 실제 숨김은 M |
| FR-HIDE-2, 4, 7 | T, M | 캡처 창 판별과 표시 여부 결정은 T. 타이핑 중 커서 숨김, Cmd+Shift+4, Cmd+Shift+5는 M |
| FR-HIDE-3, 6 | I, M | 심볼 미발견 처리 코드 검사, 재표시 위치 확인 |
| FR-PROC-1 | T | 실행 인자 해석 |
| FR-PROC-2 ~ 6 | M | 설정 창 열기, 설정 변경이 배지에 반영됨, 창 닫으면 설정 프로세스 종료 |
| FR-STYLE-2, 3, 5 | T | 경계값, 범위 밖 값, 모서리 둥글기 상한, 테두리 포함 크기·위치·바깥 반지름 |
| FR-STYLE-4, 6 | M | 긴 글자가 배경 밖으로 나가지 않는다. 글자 테두리를 두껍게 해도 글자 획 굵기가 같다 |
| UI-6, 9, 10 | T, M | 미리보기 배치 계산은 T. 화면 표시와 커서 종류 전환은 M |
| FR-CAPS-2, 3 | T, M | 표시 글자 결정은 T. Caps Lock을 켜고 끌 때 배지 변화는 M |
| FR-EMPH-1, 3, 5 | T | 값 범위 보정, 확대 창 크기와 위치 계산 |
| FR-EMPH-2, 4 | M | 전환 때 확대 후 복귀, 숨김 중에는 강조 없음 |
| FR-MODE-2 ~ 5, 7 | T | 모드별 불투명도 계산, 경계 시점, 값 범위 보정 |
| FR-MODE-6, 8 | M | 부드러운 전환, 대기 시간 뒤 불투명도 변화 |
| UI-8, 11 | M | '동작' 화면 위치와 구성 |
| FR-SRC-3, 4, 7, 9 | T | 스타일 결정 로직 |
| FR-SRC-5, 6 | T | 0자, 8자, 9자, 결합 문자, 이모지, 각 언어 코드, 언어 코드 없음, 이름 없음 |
| FR-SRC-8 | T | 목록에서 빠진 ID의 설정이 저장소에 남는다 |
| FR-STORE-2, 4, 5, 6, 7 | T | 왕복 인코딩, 손상된 JSON, 범위 밖 저장값, 스키마 버전 1·2 저장값 |
| FR-APP-1 ~ 5 | M | 메뉴 동작, 설정 창 단일성, 자동 실행 토글 |
| PR-3 | M | `ps`로 1분간 5초마다 CPU 측정 |
| PR-4 | M | `footprint` 명령으로 측정 |
| PR-5 | M | 설정 창을 열고 슬라이더를 끄는 동안 마우스를 움직여 배지 추적 확인 |
| C-4, QA-3 | M, I | 첫 실행 시 권한 대화상자가 뜨지 않는다 |

## 5. 추적성

| 사용자 요구 (인터뷰) | 요구사항 |
|---|---|
| 한/영을 포함한 현재 입력 상태 감지 | FR-DET-1 ~ 5, SI-1 ~ 4 |
| 마우스 포인터 옆 표시, 항상 표시 | FR-BADGE-1 ~ 11 |
| 글자 + 상태별 배경색 (C안) | UI-1, FR-SRC-6, FR-SRC-7 |
| 크기·위치·글자·배경 크기·색 전부 설정 | FR-STYLE-1 ~ 4 |
| 배경 테두리·글자 테두리 (두께, 색, 기본 투명) | FR-STYLE-1, 5, 6, FR-STORE-6 |
| 미리보기에 실제 커서와 배지를 함께 표시 | UI-6, 9, 10 |
| Caps Lock 표시 (기본 적용) | FR-CAPS-1 ~ 4 |
| 전환 순간 강조 (설정에서 선택) | FR-EMPH-1 ~ 5, UI-11 |
| 표시 모드 (설정에서 선택) | FR-MODE-1 ~ 8, UI-11 |
| 활성화된 모든 입력 소스별 설정 | FR-SRC-1 ~ 9 |
| macOS 네이티브, 설정 UI | C-2, UI-2 ~ 8 |
| 자동 저장, 자동 실행 | FR-STORE-1 ~ 5, FR-APP-3, 4 |
| 커서가 안 보일 때 배지도 숨김 (수동 시험 피드백) | FR-HIDE-1 ~ 3 |
| Space 전환·미션 컨트롤에서 배지가 이상함 (수동 시험 피드백) | FR-BADGE-8, FR-BADGE-12 |
| 화면 캡처 중 배지가 고정됨 (수동 시험 피드백) | FR-HIDE-4, 6, 7 |
| 설정 중 배지 지연 (수동 시험 피드백) | FR-PROC-1 ~ 6, PR-5 |
