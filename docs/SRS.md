## 1. 서론

### 1.1 목적

이 문서는 ImeCursor의 요구사항을 정의한다. ImeCursor는 macOS에서 현재 선택된 키보드 입력 소스를 마우스 포인터 옆과 텍스트 캐럿 옆에 배지로 표시하는 상주 앱이다. 이 문서는 설계, 테스트, 구현, 인수의 기준이 된다.

### 1.2 범위

ImeCursor는 다음 일을 한다.

- 현재 선택된 키보드 입력 소스를 감지한다.
- 입력 소스에 맞는 배지를 마우스 포인터 옆에 표시한다. 커서가 숨겨졌을 때와 화면 캡처 중일 때는 배지를 숨긴다.
- 사용자가 켜면, 입력 소스에 맞는 배지를 텍스트 캐럿 옆에도 표시한다. 이 기능은 접근성 권한을 쓴다.
- 사용자가 활성화된 입력 소스마다 배지의 글자와 모양을 설정할 수 있게 한다.

다음 일은 이번 범위에 들어가지 않는다(비목표).

- 접근성 API가 캐럿 위치를 주지 않는 앱(Java 앱, 게임 등)에서의 캐럿 배지 표시
- 앱이 접근성 정보를 늦게 갱신해서 생기는 캐럿 배지의 지연 해소 (예: Chrome)
- 설정 가져오기와 내보내기
- 앱별 예외 규칙 (특정 앱에서 숨기기 등)
- 마우스가 멈췄을 때 배지를 흐리게 하는 기능
- 자동 업데이트
- 입력 소스 전환 기능 (ImeCursor는 표시만 하고 전환하지 않는다)

### 1.3 용어 정의

| 용어 | 정의 |
|---|---|
| 입력 소스 | macOS가 관리하는 키보드 입력 단위. 키보드 레이아웃(예: `ABC`)과 입력기 모드(예: `두벌식`)를 포함한다 |
| 입력 소스 ID | 입력 소스를 구분하는 문자열. `kTISPropertyInputSourceID` 값이다. 예: `com.apple.inputmethod.Korean.2SetKorean` |
| 활성 입력 소스 | 시스템 설정에 추가되어 있고 사용자가 선택할 수 있는 입력 소스 |
| 현재 입력 소스 | 지금 선택된 입력 소스 |
| 배지 | 입력 소스를 나타내는 사각형. 배경과 글자로 구성된다. 커서 배지와 캐럿 배지가 있다 |
| 커서 배지 | 마우스 포인터 옆에 표시되는 배지 |
| 캐럿 배지 | 텍스트 캐럿 옆에 표시되는 배지 |
| 캐럿 | 포커스 요소 안에서 글자가 입력될 위치를 나타내는 표시. 텍스트 커서라고도 한다 |
| 캐럿 사각형 | 캐럿의 화면 위치와 크기. 너비는 0일 수 있다 |
| 포커스 요소 | 키보드 입력을 받는 UI 요소. 시스템 전체 접근성 요소의 `AXFocusedUIElement` 값이다 |
| AX | macOS 접근성 API (`ApplicationServices`의 `AXUIElement` 계열 함수) |
| 스타일 | 배지의 모양을 정하는 값의 묶음. 3.2.3절에 정의한다 |
| 기본 스타일 | 커서 배지와 캐럿 배지가 함께 쓰는 공통 스타일. 오프셋은 포함하지 않는다(FR-STYLE-7) |
| 기준 방향 | 대상 사각형의 9개 점(왼쪽 위, 위 가운데, 오른쪽 위, 왼쪽 가운데, 가운데, 오른쪽 가운데, 왼쪽 아래, 아래 가운데, 오른쪽 아래) 가운데 하나. 배지를 대상의 어느 쪽에 놓을지 정한다(FR-STYLE-8) |
| 대상 사각형 | 배지를 붙일 기준. 커서 배지는 포인터 핫스폿에 놓인 크기 0의 사각형, 캐럿 배지는 캐럿 사각형이다 |
| 위치 기본값 | 배지별 기준 방향, 오프셋 X, Y의 기본값. 커서 배지와 캐럿 배지가 각각 가진다 |
| 덮어쓰기 | 한 입력 소스의 한 배지에서 기본 스타일 또는 위치 기본값과 다르게 정한 항목. 정하지 않은 항목은 기본값을 따른다 |
| TIS | Carbon Text Input Sources API |
| 배지 프로세스 | 배지를 그리고 포인터를 추적하는 ImeCursor 프로세스. 인자 없이 실행된다 |
| 설정 프로세스 | 설정 화면만 띄우는 ImeCursor 프로세스. `--settings` 인자로 실행된다 |
| 캡처 창 | 창 목록(`CGWindowListCopyWindowInfo`)의 화면 위 창 가운데 다음에 해당하는 창. (1) 소유 프로세스 이름이 `screencapture`인 창 (Cmd+Shift+3/4). (2) 소유 프로세스 이름이 `Screenshot`이고 레이어가 화면 보호기 레벨(`CGWindowLevelForKey(.screenSaverWindow)`, 측정값 1000)보다 높은 창 (Cmd+Shift+5) |
| pt | macOS 좌표계의 포인트 단위 |

## 2. 전체 설명

### 2.1 제품 관점

ImeCursor는 단독으로 실행되는 macOS 앱이다. Dock 아이콘 없이 메뉴바 아이콘으로만 존재한다(`LSUIElement`). 다른 앱이나 서버와 통신하지 않는다.

구성 요소는 다음과 같다.

| 구성 요소 | 역할 |
|---|---|
| 입력 소스 감지기 | TIS API로 현재 입력 소스와 활성 입력 소스 목록을 읽는다. 변경 알림을 받는다 |
| 커서 배지 창 | 테두리 없는 투명 창. 포인터를 따라 움직인다 |
| 캐럿 배지 창 | 테두리 없는 투명 창. 캐럿을 따라 움직인다 |
| 포인터 추적기 | 마우스 이동 이벤트를 받아 커서 배지 창의 위치를 갱신한다 |
| 캐럿 추적기 | AX로 포커스 요소의 캐럿 사각형을 읽어 캐럿 배지 창의 위치를 갱신한다 |
| 숨김 감시기 | 주기마다 커서 표시 상태와 캡처 창을 확인하여 배지를 숨길지 정한다 |
| 설정 저장소 | 스타일을 `UserDefaults`에 저장하고 읽는다 |
| 설정 화면 | SwiftUI 창. 입력 소스별 스타일을 편집한다. 설정 프로세스에서만 실행된다 |
| 메뉴바 메뉴 | 배지 켜기/끄기, 설정 열기, 종료. 배지 프로세스에 있다 |

배지 프로세스와 설정 프로세스는 같은 실행 파일과 같은 번들 ID를 쓴다. 두 프로세스는 같은 `UserDefaults` 도메인을 공유하고, 분산 알림으로 설정 변경을 서로 알린다.

### 2.2 제품 기능 요약

1. 현재 입력 소스 감지와 변경 감지
2. 포인터 옆 배지 표시와 추적
3. 캐럿 옆 배지 표시와 추적 (선택, 접근성 권한 필요)
4. 입력 소스별, 배지별 스타일 설정과 미리보기
5. 설정 자동 저장
6. 로그인 시 자동 실행 선택

### 2.3 사용자 특성

사용자는 macOS를 쓰고 두 개 이상의 입력 소스를 전환하는 사람이다. 개발 지식은 필요 없다.

### 2.4 제약 사항

| ID | 제약 |
|---|---|
| C-1 | macOS 14 (Sonoma) 이상에서 동작해야 한다 |
| C-2 | Swift와 Apple 기본 프레임워크(AppKit, SwiftUI, Carbon, ServiceManagement)만 쓴다. 외부 패키지를 쓰지 않는다 |
| C-3 | Xcode 없이 Command Line Tools의 SwiftPM으로 빌드한다. `.app` 번들은 스크립트로 만든다. CLT에는 SwiftUI 매크로 플러그인이 없으므로 `@State` 등 매크로 기반 SwiftUI 속성을 쓰지 않는다. Swift Testing 매크로 플러그인 경로는 테스트 스크립트에서 지정한다 |
| C-4 | 캐럿 배지가 꺼져 있으면 사용자 승인이 필요한 권한을 요구하지 않는다. 캐럿 배지가 켜져 있을 때만 접근성 권한을 쓴다. 입력 모니터링, 화면 기록 권한은 어떤 경우에도 요구하지 않는다 |
| C-5 | 테스트는 Swift Testing 프레임워크로 작성한다 |
| C-6 | 네트워크를 쓰지 않는다 |

| A-5 | `CGCursorIsVisible`은 다른 앱이 숨긴 커서도 반영한다 (2026-10-27 측정으로 확인함) |

| A-9 | 접근성 권한이 있으면 다음 앱에서 AX로 캐럿 사각형을 얻을 수 있다: 네이티브 앱, VS Code, Terminal, Chrome의 웹 입력란과 xterm.js 웹 터미널 (2026-10-28 프로브 측정으로 확인함) |

Chrome은 `AXEnhancedUserInterface`를 true로 설정해야 입력란의 캐럿 사각형을 준다. 이 설정은 2 ~ 3초 뒤에 효과가 나고, 효과가 있어도 오류 코드 -25208을 돌려준다. 설정 전에는 x = 0인 사각형, 웹 영역 원점 같은 엉뚱한 점, 입력란 전체 사각형을 캐럿 대신 준다. 빈 입력란에서는 캐럿 사각형을 주지 않는다. Gmail, Google Chat, 검색창에서 설정한 동안 중복 입력, 한글 조합 오류, 화면 지연은 관찰되지 않았다 (2026-10-28 측정으로 확인함) |
| A-11 | xterm.js는 숨겨진 입력 요소(`AXTextField`, 글자 수 0)를 터미널 커서 칸으로 옮긴다. 이 요소의 크기는 글자 한 칸이다 (2026-10-28 측정으로 확인함) |
| A-12 | Spotlight는 맨 앞 앱이 되지 않고 키보드 포커스만 가져간다. 포커스 요소는 `Siri` 프로세스에 속한다. 시스템 전체 요소의 `AXFocusedUIElement`로 이 요소를 얻을 수 있다 (2026-10-28 측정으로 확인함) |
| A-13 | 편집할 수 없는 웹 페이지에서도 Chrome은 선택 위치를 텍스트 마커로 준다. 편집 가능한 요소는 `AXEditableAncestor`가 있거나 `AXSelectedTextRange`를 설정할 수 있다. Spotlight 입력란은 `AXEditableAncestor`가 없다. 탭 버튼은 `AXValue`를 설정할 수 있으므로 `AXValue`로는 판별할 수 없다 (2026-10-28 측정으로 확인함) |
| A-14 | 접근성 권한은 앱의 코드 서명에 묶인다. ad-hoc 서명(A-4)은 다시 빌드할 때마다 바뀌므로, 다시 빌드한 앱은 권한을 다시 허용해야 한다 |
| A-8 | 화면 캡처 모드에서는 전역 마우스 이벤트가 오지 않는다. 캡처 모드 동안 캡처 창이 화면에 있다. 평소 `Screenshot` 프로세스에는 레이어 24 창만 있다 (2026-10-27 측정으로 확인함). 창 이름은 화면 기록 권한이 없으면 읽지 못할 수 있으므로 판별에 쓰지 않는다 |

A-1은 2026-10-27 수동 시험에서 확인했다.

#### 3.2.2C 전환 강조 (FR-EMPH)

"전환"은 현재 입력 소스가 바뀌거나 Caps Lock 상태가 바뀌는 것을 말한다. 전환 강조 설정은 커서 배지와 캐럿 배지가 각각 가진다. 이 절의 요구사항은 각 배지에 따로 적용한다.

| ID | 요구사항 |
|---|---|
| FR-EMPH-1 | 전환 강조 설정은 켜기 여부, 확대 배율, 지속 시간으로 구성한다. 범위와 초기값은 다음과 같다: 켜기 여부(초기값 꺼짐), 확대 배율 1.0 ~ 3.0(초기값 1.6), 지속 시간 0.1 ~ 1.0초(초기값 0.35) |
| FR-EMPH-2 | 전환 강조가 켜져 있으면, 전환이 일어날 때 배지를 확대 배율로 키운 뒤 지속 시간 동안 원래 크기로 줄여야 한다. 확대와 축소의 중심은 배지(테두리 포함)의 가운데이다 |
| FR-EMPH-3 | 확대된 배지가 잘리지 않도록 배지 창은 `배지 전체 크기 × 확대 배율` 크기여야 하고, 배지는 창 가운데에 놓아야 한다. 화면 경계 보정(FR-BADGE-3)은 확대하지 않은 배지 기준으로 한다 |
| FR-EMPH-4 | 배지가 숨김 상태(커서 배지: FR-HIDE, FR-BADGE-9, 10, 13. 캐럿 배지: FR-CARET-3)이면 강조하지 않는다 |
| FR-EMPH-5 | 범위를 벗어난 값은 가장 가까운 경계값으로 바꿔야 한다 |

표시 모드 설정은 커서 배지와 캐럿 배지가 각각 가진다. 이 절의 요구사항은 각 배지에 따로 적용한다.

| ID | 요구사항 |

#### 3.2.2E 캐럿 배지 (FR-CARET)

| ID | 요구사항 |

(1) `AXSelectedTextRange`의 끝 위치 e에 대해 `AXBoundsForRange`를 다음 순서로 묻는다: 범위 (e, 0)의 사각형 → 범위 (e − 1, 1)의 오른쪽 변(e > 0일 때) → 범위 (e, 1)의 왼쪽 변. (2) `AXSelectedTextMarkerRange`의 끝 마커 m에 대해 `AXBoundsForTextMarkerRange`를 다음 순서로 묻는다: 범위 (m, m)의 사각형 → `AXPreviousTextMarkerForTextMarker`로 구한 앞 마커 p에 대해 범위 (p, m)의 오른쪽 변. (3) 포커스 요소의 사각형(`AXPosition`, `AXSize`)이 높이 40 pt 이하이고 폭이 높이 이하이면 그 사각형을 쓴다(A-11). (4) 포커스 요소의 글자 수(`AXNumberOfCharacters`)가 0이면, 요소 사각형의 왼쪽 위 모서리에 너비 0, 높이 20 pt인 사각형을 쓴다. 이것도 얻지 못하면 캐럿 사각형이 없는 것으로 본다. "오른쪽 변", "왼쪽 변"은 그 사각형의 오른쪽 또는 왼쪽 x에 놓인 너비 0, 같은 높이의 사각형이다 |
| FR-CARET-6 | (1), (2)에서 얻은 사각형은 다음 조건을 모두 만족할 때만 유효하다. (a) x가 0이 아니다. (b) 왼쪽 위 점이 어느 화면 영역 안에 있다. (c) 너비가 `max(높이, 1)` 이하이다. 줄이나 입력란 전체의 사각형을 거르기 위함이다. (d) 점 (x, 세로 가운데)가 포커스 요소 사각형을 사방 4 pt 넓힌 영역 안에 있다. 웹 영역 원점 같은 엉뚱한 점을 거르기 위함이다. 너비와 높이는 0이어도 된다(A-10) |
| FR-CARET-7 | 캐럿 배지는 캐럿 사각형을 대상 사각형으로 하여 FR-STYLE-8의 규칙으로 놓아야 한다 |
| FR-CARET-8 | 캐럿 배지에도 FR-BADGE-3의 화면 경계 보정을 적용해야 한다. 기준 화면은 캐럿 사각형의 왼쪽 위 점이 있는 화면이다 |
| FR-CARET-9 | 캐럿 배지 표시 조건이 "끄기"가 아니고 접근성 권한이 있을 때, 앱이 맨 앞으로 오면 그 앱의 앱 요소에 다음을 한 번 설정해야 한다(A-10). (1) 모든 앱: `AXManualAccessibility`를 true로 설정한다. (2) Chromium 브라우저: `AXEnhancedUserInterface`를 true로 설정한다. Chromium 브라우저는 번들 ID가 `com.google.Chrome`, `com.google.Chrome.beta`, `com.google.Chrome.canary`, `com.microsoft.edgemac`, `com.brave.Browser`, `company.thebrowser.Browser`, `com.vivaldi.Vivaldi`, `com.operasoftware.Opera` 중 하나인 앱이다. 설정의 반환값은 무시한다 |
| FR-CARET-12 | FR-CARET-9 (2)로 `AXEnhancedUserInterface`를 켠 앱은 기록해 두어야 한다. 캐럿 배지 표시 조건을 "끄기"로 바꾸거나 배지 프로세스가 종료될 때, 기록한 앱 가운데 아직 실행 중인 앱의 `AXEnhancedUserInterface`를 false로 되돌려야 한다 |

| FR-STYLE-2 | 허용 범위를 벗어난 값은 가장 가까운 경계값으로 바꿔야 한다. 색의 각 성분도 0 ~ 1로 바꿔야 한다 |
| FR-STYLE-3 | 그릴 때 적용하는 모서리 둥글기는 `min(모서리 둥글기, 배경 폭 / 2, 배경 높이 / 2)`이어야 한다 |
| FR-STYLE-4 | 글자가 배경보다 넓으면 배경 밖으로 넘치지 않게 잘라서 그려야 한다. 글자 테두리도 같다 |

(3) 맞춤점이 기준점에 오도록 배지를 놓는다. (4) 오프셋을 더한다. X는 오른쪽이 양수, Y는 아래쪽이 양수이다. (5) 화면 경계 보정(FR-BADGE-3, FR-CARET-8)을 적용한다 |

#### 3.2.4 입력 소스별 설정 (FR-SRC)

| ID | 요구사항 |
|---|---|
| FR-SRC-1 | 입력 소스마다 "표시 글자", "커서 배지 덮어쓰기", "캐럿 배지 덮어쓰기"를 저장해야 한다. 키는 입력 소스 ID이다. 표시 글자는 두 배지가 함께 쓴다 |
| FR-SRC-2 | 덮어쓰기는 FR-STYLE-1의 항목마다 값이 있거나 없다. 값이 있는 항목만 저장해야 한다 |
| FR-SRC-3 | 배지를 그릴 스타일은 항목마다 다음 순서로 정해야 한다: 그 배지의 덮어쓰기 값 → 기준 방향과 오프셋이면 그 배지의 위치 기본값, 그 밖의 항목이면 기본 스타일 값. 기본 스타일이나 위치 기본값이 바뀌면 덮어쓰지 않은 항목에 바로 반영되어야 한다 |

| FR-SRC-6 | 저장된 설정이 없는 입력 소스의 표시 글자는 언어 코드로 정해야 한다: `ko` → `한`, `en` → `A`, `ja` → `あ`, `zh`로 시작 → `中`. 그 밖의 언어는 언어 코드의 앞 두 글자를 대문자로 쓴다(예: `de` → `DE`). 언어 코드가 없으면 시스템 표시 이름의 첫 글자를 쓴다. 이것도 없으면 `?`를 쓴다 |

| FR-SRC-8 | 활성 목록에서 빠진 입력 소스의 설정은 지우지 않고 보관해야 한다. 다시 활성화되면 보관한 설정을 써야 한다 |

(2) 커서 배지 위치 기본값은 기준 방향 오른쪽 아래(↘)와 기존 기본 스타일의 오프셋이다. 이렇게 하면 기존 위치가 그대로 유지된다. 캐럿 배지 위치 기본값은 초기값이다. (3) "개별 설정"인 입력 소스는, 개별 스타일에서 기존 기본 스타일과 값이 다른 항목만 커서 배지 덮어쓰기로 바꾼다. 오프셋은 기존 기본 스타일의 오프셋과 비교한다. 기준 방향은 덮어쓰지 않는다. (4) "기본 스타일 사용"인 입력 소스는 커서 배지 덮어쓰기가 없다. (5) 기존 입력 소스의 캐럿 배지 덮어쓰기는 FR-SRC-7의 값이다. (6) 저장된 표시 글자는 그대로 둔다 |
